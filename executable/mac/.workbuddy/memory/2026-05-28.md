# 2026-05-28

## DMG Volume Icon Fixed — Package Script Works

**Root cause**: `hdiutil convert` (UDRW→UDZO) drops the `SetFile -a C` custom icon flag, so `create-dmg` applies it correctly but the compression step silently discards it.

**Fix implemented in `tools/package.sh`**:
1. After `create-dmg` finishes, re-attach UDZO DMG with shadow file (`hdiutil attach -shadow`)
2. Verify `.VolumeIcon.icns` exists on mounted volume
3. Re-apply `SetFile -a C /Volumes/...`
4. Eject, then bake shadow into final DMG: `hdiutil convert -format UDZO -o <out> <src> -shadow <shadow>`
5. Replace original with baked version

**Additional fixes along the way**:
- VolumeIcon.icns: Rebuilt from `kilo/mac/Icon.iconset` with sRGB color space (was Gray) using `sips --matchTo`
- Mount point extraction: Switched to `hdiutil attach -plist` + Python `plistlib` to handle volume names with spaces
- Shadow baking: Output to temp dir to avoid `.dmg.dmg` suffix from `hdiutil convert -o` auto-appending

**Result**: `package.sh` runs successfully, DMG shows custom volume icon on mount.

## Permanently Fixed: Patched create-dmg in tools/

Instead of hacking `package.sh` with post-processing, the fix is now inside `tools/create-dmg` (local copy of Homebrew's create-dmg 1.2.3):
- After `hdiutil convert` (UDRW→UDZO), attaches final DMG with shadow file
- Re-applies `SetFile -a C` (custom icon flag dropped by convert)
- Bakes shadow back into final DMG

`package.sh` now simply calls `./create-dmg` — no post-processing hack needed.
Verified: `.VolumeIcon.icns` exists (114487 bytes), GetFileInfo shows `C` attribute set.
